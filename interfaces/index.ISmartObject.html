    Interface ISmartObject

    The whole "smart object" contract: read, probe, write, remove, enumerate, seed and clear values by key. Every implementation in this folder (FlatObject, NestedObject, ImmutableObject) exposes exactly these seven methods and nothing more.

    It is intentionally a small, dumb concept. What a key means is left entirely to the implementation — a literal property name for FlatObject, a separator-delimited path for NestedObject, and so on — so callers can swap one implementation for another without changing their code, and a wrapper can layer behaviour on top (immutability, copy-on-write, validation, logging, change events, access control…) by holding another ISmartObject and forwarding these same calls. Keeping the surface this narrow is what makes that encapsulation cheap; richer needs (merging, transactions) belong in a wider interface built on top, not here.
