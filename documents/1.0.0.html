    1.0.0 — upgrading from 0.32.0

    1. Breaking changes for 0.32.0 consumers

    1.1 ISubscribable and Subscribable redesigned

    The single-channel subscribable, with numeric ids, is replaced by a typed, multi-event one built on EventBus.

    0.32.0 1.0.0
    ISubscribable<TData, TId = number> ISubscribable<TEvents extends EventsDefinition>
    subscribe(subscription): TId on(event, handler): EventSubscription
    unsubscribe(id): void subscription.dispose(): Promise<void>
    Subscribable<TData>.notifyData(data) this._eventBus.trigger(event, ...args) (protected, from a subclass)
    Subscription<TData> type removed, use EventHandler<TEvents, TKey>
    — dispose(): Promise<void> removes every handler

    ISubscribable now extends IDisposable and exposes only on(): raising the events is up to the implementation.

    Before

    import { Subscribable, Subscription } from "@mantlebee/ts-core";

    const counterChanged = new Subscribable<number>();

    const id = counterChanged.subscribe((value) => console.log(value));
    counterChanged.notifyData(1);
    counterChanged.unsubscribe(id);

    After — declare the events and raise them from a subclass:

    import { Subscribable } from "@mantlebee/ts-core";

    type CounterEvents = { changed: [value: number] };

    class Counter extends Subscribable<CounterEvents> {
      private value = 0;
      public increment(): void {
        this._eventBus.trigger("changed", ++this.value);
      }
    }

    const counter = new Counter();
    const subscription = counter.on("changed", (value) => console.log(value));
    counter.increment();
    await subscription.dispose(); // was: unsubscribe(id)
    await counter.dispose(); // removes every handler

    If you just need a standalone channel, without a subclass, use EventBus directly:

    import { EventBus } from "@mantlebee/ts-core";

    const bus = new EventBus<{ changed: [value: number] }>();
    const subscription = bus.on("changed", (value) => console.log(value));
    bus.trigger("changed", 1); // was: notifyData(1)
    await subscription.dispose();

    Classes implementing ISubscribable must switch to the new contract. Composition with an EventBus is the simplest way, when the class already extends something else:

    // Before
    class Store implements ISubscribable<State> {
      private subscribable = new Subscribable<State>();
      public subscribe(subscription: Subscription<State>): number {
        return this.subscribable.subscribe(subscription);
      }
      public unsubscribe(id: number): void {
        this.subscribable.unsubscribe(id);
      }
    }

    // After
    import {
      EventBus,
      EventHandler,
      EventSubscription,
      ISubscribable,
      KeyOf,
    } from "@mantlebee/ts-core";

    type StoreEvents = { changed: [state: State] };

    class Store implements ISubscribable<StoreEvents> {
      private eventBus = new EventBus<StoreEvents>();

      public dispose(): Promise<void> {
        return this.eventBus.dispose();
      }
      public on<TKey extends KeyOf<StoreEvents>>(
        event: TKey,
        handler: EventHandler<StoreEvents, TKey>,
      ): EventSubscription {
        return this.eventBus.on(event, handler);
      }
      private setState(state: State): void {
        this.eventBus.trigger("changed", state);
      }
    }

    1.2 SubscribableLogger uses events

    SubscribableLogger now implements ISubscribable<SubscribableLoggerEvents>: every entry raises the log event with a SubscribableLoggerData payload (unchanged: type, message, data).

    0.32.0 1.0.0
    subscribe(subscription): number on("log", handler): EventSubscription
    unsubscribe(id): void subscription.dispose()
    — dispose() removes every handler
    — new type SubscribableLoggerEvents 
    const logger = new SubscribableLogger();

    // Before
    const id = logger.subscribe(({ type, message }) => show(type, message));
    logger.unsubscribe(id);

    // After
    const subscription = logger.on("log", ({ type, message }) =>
      show(type, message),
    );
    await subscription.dispose();

    1.3 Exception extends BaseException

    Exception keeps its (code, message) constructor and its required code, so existing subclasses compile unchanged. What changes:

    • it extends the new BaseException (which extends Error), so error instanceof BaseException is true for every library exception;
    • name is now "Exception" instead of "Error";
    • the constructor accepts an optional third argument, cause.

    Only code that checks error.name === "Error" needs an update. Subclasses should set their own name, because class names don't survive minification:

    class OrderException extends Exception {
      public constructor(code: string, message: string, cause?: unknown) {
        super(code, message, cause);
        this.name = "OrderException";
      }
    }

    // Branch on the type or the code, never on the message
    if (error instanceof BaseException && error.code === "ORD-1") ...

    New code that doesn't need a mandatory code can extend BaseException directly:

    import { BaseException, ExceptionOptions } from "@mantlebee/ts-core";

    class QuotaExceededException extends BaseException {
      public constructor(message = "Quota exceeded", options?: ExceptionOptions) {
        super(message, options); // options: { code?, cause? }
        this.name = "QuotaExceededException";
      }
    }

    1.4 New names in the public barrel

    Everything is still re-exported flat from @mantlebee/ts-core, which now includes many new names (see What's new). If your project re-exports the library (export * from "@mantlebee/ts-core") next to its own modules, TypeScript reports a conflict (TS2308) for every name defined on both sides, e.g. Validator, Validation, Notifier, LocalStorage, getHumanFileSize. Fix it by removing your duplicate or by re-exporting explicitly:

    export * from "@mantlebee/ts-core";
    export { Validator } from "./my-validators"; // explicit export wins

    1.5 Package entry points

    The package now declares its entry points in exports: import resolves to an ES modules build (one file per module, so bundlers can drop what you don't use) and require to the CommonJS bundle. Only the package root and @mantlebee/ts-core/package.json can be imported: deep imports such as @mantlebee/ts-core/dist/index.js no longer resolve.

    // Before
    const { Color } = require("@mantlebee/ts-core/dist/index.js");

    // After
    const { Color } = require("@mantlebee/ts-core");

    The package no longer contains the API documentation, which is published at mantlebee.github.io/ts-core.

    3. Checklist

    1. Update the dependency: npm install @mantlebee/ts-core@^1.0.0.
    2. Replace subscribe/unsubscribe/notifyData with on/dispose/trigger (1.1, 1.2).
    3. Look for error.name === "Error" checks on library exceptions (1.3).
    4. Run the type checker (tsc --noEmit): name conflicts and the removed Subscription type show up here.
    5. Replace deep imports (@mantlebee/ts-core/dist/...) with the package root (1.5).
