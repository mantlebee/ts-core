    1.2.0 — upgrading from 1.1.0

    Version 1.2.0 adds the ability to cancel a pending DebouncedDelegate. There are no breaking changes: existing code keeps compiling and behaving the same.

    • 1. DebouncedDelegate abort
    • 2. Checklist

    1. DebouncedDelegate abort

    DebouncedDelegate collapses bursts of call(...args) into one execution of the wrapped function, once the calls stop for the configured delay. Until 1.1.0 a scheduled execution could not be cancelled: the only way to stop it was to let it run, which made the class unsuitable for objects with a dispose() (the delegate could fire after its owner was disposed).

    API 1.1.0 1.2.0
    DebouncedDelegate.abort() — cancels the pending execution, if any; the arguments of the cancelled call are discarded
    DebouncedDelegate.isPending — true while a call is scheduled and not yet executed

    Both members are part of IDebouncedDelegate too, so custom implementations of the interface must add them.

    import { DebouncedDelegate } from "@mantlebee/ts-core";

    class SearchBox {
      private readonly _search = new DebouncedDelegate(
        (text) => this.fetch(text as string),
        300,
      );

      public onInput(text: string): void {
        this._search.call(text);
      }
      public dispose(): void {
        // Nothing runs after this point, even if a call was pending.
        this._search.abort();
      }
    }

    abort() on a delegate with nothing pending does nothing. A call() after an abort() starts a new wait as usual.

    2. Checklist

    1. Update the dependency: npm install @mantlebee/ts-core@^1.2.0.
    2. If you implement IDebouncedDelegate yourself, add abort() and isPending: the type checker (tsc --noEmit) points them out.
    3. Where an object owning a DebouncedDelegate has a dispose() or a teardown, call abort() there to drop pending executions.
