# 1.4.0 — upgrading from 1.3.1

Version 1.4.0 fixes how `createHttpGetQuery` serializes the query string of a
GET request: lists are sent as repeated keys instead of being comma-joined,
`Date`s as ISO 8601 strings instead of their locale representation, and
objects are rejected instead of being sent as `[object Object]`. The
serializer is now pluggable through `HttpRequestorOptions`. The type of the
parameters is narrower than before, so code that passed objects or other
non-primitive values stops compiling: this is intended, see section 1.

## 1. Query string serialization

`createHttpGetQuery` (used by `FetchApiHttpRequestor.get`) skipped `null` and
`undefined` and converted everything else with `String(value)`, which is what
`URLSearchParams` itself does. The result was lossy for every non-primitive
value: a list `[1, 2]` became `a=1%2C2`, a single comma-joined value the
receiver cannot tell from the string `"1,2"`; an object `{ x: 1 }` became
`c=%5Bobject+Object%5D`, i.e. `[object Object]`; a `Date` became its
locale-dependent `toString()` (`Thu Jan 01 2026 01:00:00 GMT+0100 (…)`). The
type of the parameters, `Dictionary<unknown>`, accepted all three without a
warning.

There is no standard for serializing lists and objects in a query string
(RFC 3986 only defines `key=value&…`): PHP, Rails and `qs` use brackets
(`a[]=1&a[]=2`, `c[x]=1`), JSON:API and OData use commas for lists, ASP.NET
and Spring accept dots for objects. The one form that every server parses
without configuration is the repeated key (`a=1&a=2`), which is also the
default of OpenAPI (`style: form, explode: true`) and the native model of
`URLSearchParams.append`. Dates do have a standard, ISO 8601, which is also
what `JSON.stringify` and Axios emit, so they are serialized with
`toISOString()` (always UTC, with the `Z` suffix). Other objects have no
convention a client library can pick for a server it doesn't know, so they
are rejected, as Angular's `HttpParams` does at the type level.

| API                          | 1.3.1                      | 1.4.0                                                              |
| ---------------------------- | -------------------------- | ------------------------------------------------------------------ |
| `HttpSearchParams`           | `Dictionary<unknown>`      | primitives, dates, lists of them, `null` and `undefined`           |
| `HttpSearchParamValue`       | —                          | `string \| number \| boolean \| bigint \| Date`                    |
| `createHttpGetQuery` lists   | comma-joined (`ids=1%2C2`) | repeated keys (`ids=1&ids=2`); `null` and `undefined` items skipped |
| `createHttpGetQuery` dates   | locale `toString()`        | ISO 8601 (`toISOString()`); an invalid date throws `BadRequestException` |
| `createHttpGetQuery` objects | `[object Object]`          | throws `BadRequestException`, naming the parameter                 |
| `FetchApiHttpRequestor.get`  | sends the lossy query      | rejects with the `BadRequestException` without sending the request |

```ts
import { createHttpGetQuery } from "@mantlebee/ts-core";

createHttpGetQuery({ page: 1, q: "a b", ids: [1, 2], filter: null });
// 1.3.1: "page=1&q=a+b&ids=1%2C2"
// 1.4.0: "page=1&q=a+b&ids=1&ids=2"

createHttpGetQuery({ from: new Date(Date.UTC(2026, 0, 1)) });
// 1.3.1: "from=Thu+Jan+01+2026+01%3A00%3A00+GMT%2B0100+(…)" (locale-dependent)
// 1.4.0: "from=2026-01-01T00%3A00%3A00.000Z"

createHttpGetQuery({ filter: { x: 1 } });
// 1.3.1: "filter=%5Bobject+Object%5D"
// 1.4.0: throws BadRequestException (and no longer compiles)
```

Scalar parameters are serialized exactly as before. A consumer that relied on
the comma-joined form of a list (because its server expects `ids=1,2`) must
join the list itself (`ids: ids.join(",")`) or set a serializer, see below.

## 2. Pluggable serializer

`HttpRequestorOptions` has a new optional `searchParamsSerializer`, an
`HttpSearchParamsSerializer`: `(searchParams: HttpSearchParams) => string`,
returning the query string without the leading `?` (an empty string sends no
query). `FetchApiHttpRequestor` uses it instead of `createHttpGetQuery`; the
proxy requestors forward the options to the inner requestor through
`withOptions`, as they do for the other options. The serializer receives the
same narrowed `HttpSearchParams`: it is meant to change the convention
(brackets, commas, another encoding), not to widen what `get` accepts. A
parameter that needs a richer shape (a nested filter as JSON) is serialized
by the caller into a string value.

| API                                           | 1.3.1 | 1.4.0                                                        |
| --------------------------------------------- | ----- | ------------------------------------------------------------ |
| `HttpRequestorOptions.searchParamsSerializer` | —     | serializer of the query string, default `createHttpGetQuery` |
| `HttpSearchParamsSerializer`                  | —     | `(searchParams: HttpSearchParams) => string`                 |

```ts
import {
  FetchApiHttpRequestor,
  HttpSearchParamsSerializer,
} from "@mantlebee/ts-core";

// Brackets, for a PHP / Rails / `qs` backend.
const bracketsSerializer: HttpSearchParamsSerializer = (params) => {
  const query = new URLSearchParams();
  Object.entries(params).forEach(([key, value]) => {
    if (Array.isArray(value))
      value.forEach((a) => a != null && query.append(`${key}[]`, String(a)));
    else if (value != null) query.append(key, String(value));
  });
  return query.toString();
};

const requestor = new FetchApiHttpRequestor({
  searchParamsSerializer: bracketsSerializer,
});
await requestor.get("/items", { ids: [1, 2] }); // GET /items?ids[]=1&ids[]=2
```

## 3. Checklist

1. Update the dependency: `npm install @mantlebee/ts-core@^1.4.0`.
2. Compile: every call of `get` or `createHttpGetQuery` that passes an object
   or a nested list is now a type error. Serialize the value into a string
   (`JSON.stringify`) or flatten it into separate parameters.
3. If you passed `Date`s and the server parsed their `toString()` form, it now
   receives ISO 8601 in UTC; if you need a date-only value (`2026-01-01`) or
   local time, format it yourself into a string, as before.
4. If a server of yours expects comma-joined lists, join them yourself or set
   a `searchParamsSerializer` on the requestor.
5. Code that passed lists and whose server already parsed `ids=1,2` as a single
   string (and split it) now receives `ids=1&ids=2`: check how that server
   reads repeated keys (most frameworks return a list, some only the last
   value).
