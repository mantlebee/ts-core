# 1.1.0 — upgrading from 1.0.0

Version 1.1.0 fixes the bugs found by a quality review of 1.0.0. There are no
new modules; a few fixes change behaviour or types that code may rely on, and
they are listed below.

- [1. Bug fixes that change behaviour](#1-bug-fixes-that-change-behaviour)
- [2. MultiTabEventBus storage keys](#2-multitabeventbus-storage-keys)
- [3. Checklist](#3-checklist)

---

## 1. Bug fixes that change behaviour

These are fixes, but code that relied on the old behaviour may notice them.

| API                                    | 1.0.0                                                                         | 1.1.0                                                                                                        |
| -------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `TypedKey<T>`                          | an empty interface: keys of any type were assignable to each other            | a branded `symbol`: `TypedKey<string>` is not assignable to `TypedKey<number>`                               |
| `isFunction` / `getValue`              | `function () {}` was not a function, so `getValue` returned it uncalled       | `function () {}` is a function and `getValue` calls it; constructors still aren't                            |
| `firstOrDefault`                       | a falsy match (`0`, `""`, `false`) returned the default item                  | the match is returned                                                                                        |
| `roundNumber`                          | wrong for numbers in exponential notation (`1.23e-7`, `1e21`)                 | correct                                                                                                      |
| `Wizard.abort`                         | threw a `TypeError` when the context had no `abort`, stuck in `aborting`      | resolves                                                                                                     |
| `Wizard.goForward` / `goBack`          | a rejected `beforeEnter` left the step history changed                        | the history changes only once the step is entered                                                            |
| `Wizard.start`                         | a rejected hook left the wizard in `starting`                                 | back to `needToStart`, so `start` can be retried                                                             |
| `Wizard.canGoForward`                  | a step outside the steps list, without `nextStep`, went back to the first one | it can't go forward                                                                                          |
| `Alarm.snooze` / `stop`                | a snooze before the alarm went off fired twice, and `stop` didn't cancel it   | a snooze replaces the pending alert; `stop` cancels everything                                               |
| `Alarm`                                | expirations beyond ~24.8 days went off immediately                            | they go off on time                                                                                          |
| `KeyedDeferred`                        | a timeout could reject a later `wait()` with the same key; never cleaned up   | timers are bound to their own promise and settled promises leave the registry; `timeoutAfter: 0` is honoured |
| `NestedObject` / `FlatObject`          | `__proto__` paths polluted `Object.prototype`; `has("toString")` was `true`   | `__proto__` writes are ignored; only own keys are read or reported                                           |
| `ImmutableObject`                      | writes to a version after `clone()` were visible in the fork                  | versions are independent; the third constructor argument (`parent`) is removed                               |
| `rgbaToHsla` / `Color.hsl()`           | saturation `NaN` for grays (`hsl(0,NaN%,0%)`)                                 | `0`                                                                                                          |
| `textToHsl` / `Color.fromText`         | the hue could be negative                                                     | always between 0 and 359 (a different color for the texts that were negative)                                |
| `WebColorNamesHexMap` / `WebColorName` | `"indianred "` (with a space); wrong `mediumpurple` and `palevioletred`       | `indianred`; CSS values; adds `rebeccapurple` and the `grey`/`gray` variants                                 |
| `tokenize`                             | crashed on matches such as `"constructor"`; looped on a backward `endIndex`   | regular tokens; always moves forward                                                                         |
| `FetchApiHttpRequestor.post`           | JSON bodies were sent without `Content-Type`                                  | `Content-Type: application/json`, unless already set                                                         |
| `FetchApiHttpRequestor.withOptions`    | shared the same `Headers` instance                                            | copies the headers                                                                                           |

## 2. MultiTabEventBus storage keys

`MultiTabEventBus` now writes every event under a prefixed key
(`multi-tab-event-bus:<event>` by default, see the new `keyPrefix` option)
together with a unique id, so repeated events with the same arguments reach
the other tabs too. In 1.0.0 the key was the bare event name and a repeated
event with the same arguments was lost.

New exports: `MultiTabEventBusMessage` (the stored payload) and
`MultiTabEventBusKeyPrefixDefault`.

Tabs running 1.0.0 and tabs running 1.1.0 don't see each other's events:
deploy the update to every tab of the application at once. Code that listens
to the `storage` event directly must look for the prefixed keys.

## 3. Checklist

1. Update the dependency: `npm install @mantlebee/ts-core@^1.1.0`.
2. Run the type checker (`tsc --noEmit`): mixed `TypedKey` types and
   `ImmutableObject` constructed with a `parent` show up here.
3. Look for `getValue` with `function` getters and for `firstOrDefault` calls
   that relied on the default item for falsy matches.
4. Check stored or compared colors that come from `WebColorName`,
   `textToHsl`/`Color.fromText` or `Color.hsl()` on grays.
5. If you use `MultiTabEventBus`, see [2](#2-multitabeventbus-storage-keys).
