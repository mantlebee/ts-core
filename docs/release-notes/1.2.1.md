# 1.2.1 — upgrading from 1.2.0

Version 1.2.1 is a bug fix release: `DebouncedDelegate` now works outside the
browser. There are no breaking changes and no API changes: existing code keeps
compiling and behaving the same.

- [1. DebouncedDelegate in Node](#1-debounceddelegate-in-node)
- [2. Checklist](#2-checklist)

---

## 1. DebouncedDelegate in Node

`DebouncedDelegate.call()` scheduled its execution with `window.setTimeout`.
In an environment without a `window` global (server-side rendering, Node
scripts, Jest with the `node` test environment) every call threw
`ReferenceError: window is not defined`, so any library or application that
debounced on the server could not use the class, even though nothing else in
it depends on the DOM.

| API                       | 1.2.0                                        | 1.2.1                                                            |
| ------------------------- | -------------------------------------------- | ---------------------------------------------------------------- |
| `DebouncedDelegate.call()` | throws `ReferenceError` where `window` is missing | uses the global `setTimeout`: works in browsers, Node and jsdom alike |

Browser code is unaffected: in a browser the global `setTimeout` is
`window.setTimeout`.

The browser-only modules (`WebClipboard`, `MultiTabEventBus`) are unchanged
and still require a browser, as their documentation states.

---

## 2. Checklist

1. Update the dependency: `npm install @mantlebee/ts-core@^1.2.1`.
2. If you shimmed `window` (e.g. `globalThis.window = globalThis`) to use
   `DebouncedDelegate` in Node, remove the shim.
